# iZiwei 排盘工具

这是一个基于 React、Vite、iztro 与 lunar-javascript 的本地优先排盘工具。

View your app in AI Studio: https://ai.studio/apps/a2858775-fa43-4fa1-a6d2-1a5099b99407

## 锁定台账与NotebookLM事实包

紫微排盘提供五种工作视图：

- `原始命盘`：用于日常查看和人工阅读。
- `锁定台账`：完整、可人工审计的Markdown事实表。
- `NotebookLM事实包`：把每个原子事实写成一整行自描述的`FACT|...`记录，是NotebookLM唯一应加载的案例盘面来源。
- `回答核验`：把NotebookLM每道题的Model回答粘贴回来，根据`E编号=事实编号`自动还原当前事实包中的完整FACT，并检查正文是否绕过编号重新书写技术关系。协议v3分层显示引用核验、核心闭包和语义角色状态；当前已为问题6实现夫妻宫核心事实闭包。
- `提问清单`：内置v0.11稳定版与v0.12候选版，按问题0至15、可选题与CP技法检查点各拆成23个复制项；默认v0.11，可随时切换或回退，构建前会从产品设计目录分别同步两个版本。

台账v4.1另外提供三类适合NotebookLM检索的原子事实：`Z`表一行记录一个星曜或神煞，`R`表直接给出每宫的对宫与两个三合宫，`A`表把F、D、DA中的禄权科忌拆成一行一条路径。分析时优先引用这些原子编号，例如`Z074`、`R11`、`F11-K`；旧B、F、D、DA表继续保留作完整盘面与兼容摘要。紫微生年四化由生成器内部读取农历生年天干，不借用八字年柱天干。

网页中的“报告日期”是M08、M10、M11、D02、D03、DA与LY的唯一时空入口，可为不同报告年份分别导出台账。D02固定作为当前大限摘要；DA从第一限顺排到当前限并额外输出下一限，每组含四化和L01-L12叠宫；D03固定使用M10报告年份天干，LY01-LY12固定记录流年十二宫落入的本命宫位。

NotebookLM建议流程：

1. 网页排盘后下载`NotebookLM事实包`，不要把完整台账或原始文字盘同时作为案例来源。
2. NotebookLM只勾选当前事实包和本题需要的课程来源。
3. 每项证据独占一行写成`E01=Z054`；每个E只绑定一个事实编号。解释正文只引用E编号，不重新口述飞化方向、对宫、三合或落点。
4. 每道题答完立即粘贴到网页`回答核验`，可手动选择题号，也可由C编号自动识别。普通题至少需要`引用核验PASS`；问题6还需要`核心闭包PASS`。若正文误写B、S、F等盘面编号且证据登记已有唯一映射，网页可直接执行`替换编号并复核`，只改编号、不改论断。若仅缺少正文E编号对应的证据映射，网页会显示`可补证`：复制自动生成的补证指令给NotebookLM，再把返回的映射行粘贴回来执行`合并复核`，原回答正文不会被改写。其他`BLOCKED`仍需按错误类型返工。
5. PASS结果末尾会生成下一题状态回执，把它放在下一道提问开头，防止同一NotebookLM对话继续回答上一题。
6. 网页顶部的`提问清单`可逐题展开和一键复制；问题14的提问与回答回传已经拆成两个复制项。v0.11是稳定基线；v0.12增加当前题范围内的资源、风险与中性结构遗漏检查，不设吉凶配额，并要求每条主方法链提供具体课程直接引用；问题1只搭本命骨架，不提前代替后续专题。

引用核验只保证声明的盘面事实忠于当前事实包，并阻断未登记的技术关系。问题6核心闭包进一步检查夫妻宫身份与关系、关键星情、生年四化、本命飞化全部出入及离心向心是否完整登记；它仍不判断这些FACT在正文中的语义角色、课程技法是否成立、推论是否足够或现实落象是否准确，不能代替人工论命审稿。

## 本地运行

**Prerequisites:**  Node.js


1. Install dependencies:
   `npm install`
2. Set the `GEMINI_API_KEY` in [.env.local](.env.local) to your Gemini API key
3. Run the app:
   `npm run dev`
